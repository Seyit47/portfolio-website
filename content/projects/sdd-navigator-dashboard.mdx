## Context

Specification-driven development only pays off when everyone can see the gap between what was
specified and what was built. The API existed; the view did not.

## What I built

A Next.js App Router dashboard with four areas: Summary, Requirements, Requirement detail, and
Tasks & orphans. Filters and sort are query parameters, so a URL is a saved view.

## Decisions

- The Next.js server calls the API; the browser only talks to the dashboard. API requests never
  appear in the browser's network tab and credentials never leave the server.
- The API accepts one value per filter parameter, so multi-select sends one request per value
  and merges results; selecting every value sends none.
- Search is applied in the browser because the API has no search parameter.
- Mock mode is the default for development, with fixtures shaped exactly like API responses.

## Result

A dashboard that can be demoed in seconds and pointed at a real project by setting one
environment variable, with Vitest unit tests, Husky and commitlint in the workflow.
